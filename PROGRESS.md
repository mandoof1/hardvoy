## Bugs found and fixed while finishing (all covered by tests or fixtures)

1. `scan.rs` test fixtures used a stale `tor::Circuit` shape and 80-char relay
   fingerprints, so the suite did not compile / three circuit-choice tests were
   wrong. Rewrote the fixtures with 40-hex fingerprints and separate
   guard/middle/exit seeds so the "same exit, different path" fallback is
   actually exercised.
2. Circuit evidence for a Tor egress was smuggled through
   `browser.payload.hardvoyMeta` and an `errors` entry with a `CIRCUIT ` prefix,
   and the browser probe overwrote it. `EgressView` now has a real
   `circuit: Option<CircuitView>` field, and a test proves it survives the JSON
   round trip that `hardvoy report` depends on.
3. `http-content` looked unstable across repeat direct runs (100 % distinct)
   because the lab listens on an ephemeral port and the hash included
   `Host: 127.0.0.1:41301`. Ports are now normalised out of the content hash
   (documented in the code, asserted by `ephemeral_lab_port_does_not_change_the_content_hash`).
   Direct stability went 34/51 → 37/51; over Tor the hash had already been
   stable, which is what pointed at the port rather than the browser.
4. The `stability` profile-difference table printed nothing at all: it grouped
   by full egress name (`direct`, `direct/rfp`, `direct/leaky`), so no pair of
   profiles was ever comparable. Now grouped by base egress; prints
   `8/17 identical …` plus the per-profile hashes.
5. Tor navigations were single-attempt, and one of three circuits in the
   reference run died on a 60 s navigation timeout. Navigate is retried once;
   if it still fails the egress records both errors instead of hiding one.
6. `hardvoy compare | head -3` panicked with a broken-pipe write error. SIGPIPE
   is set to default in `main`, so a CLI with a closed stdout exits quietly.
7. `tools/make-assets.sh` built a malformed `file://` URL (absolute path joined
   onto `$PWD`), which hung the headless screenshot. Fixed with `readlink -f`
   and a `timeout`.

## Decisions worth knowing

* `hardvoy` starts **its own** Tor (own data dir, SOCKS port, control port with
  cookie auth) so NEWNYM and circuit evidence exist; `--tor-state` keeps guards
  and the onion key warm between runs, which is what makes the 5-run stability
  suites affordable (~35 s instead of a cold bootstrap each time).
* The lab, not a third-party service, is the audit target. That is also why the
  lab deliberately plants jitter (canvas raster, sub-pixel layout, sub-millisecond
  timers): five of the seventeen families are *supposed* to be unstable.
* Suricata/tshark are inventory only; no capture tooling is required at runtime.

## Reproduce everything

```bash
make test          # 133 unit tests, offline
make demo-direct   # single egress, ~6 s
make demo          # direct + three Tor circuits, ~7 min
make stability     # stability + profile-difference tables
make bench         # timing table -> docs/BENCH.md
make assets        # regenerate README images (RUN_TOR=1 to redo the Tor table too)
```
